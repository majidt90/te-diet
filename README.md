# te-diet — دستیار تغذیه و مربی ورزشی هوشمند

یک اپلیکیشن دسکتاپ با **Electron** که کل تعامل کاربر از طریق یک چت‌باکس با هوش مصنوعی انجام می‌شود. رابط کاملاً **فارسی و راست‌چین (RTL)** با فونت **وزیرمتن**، تقویم **شمسی (جلالی)** و **اعداد فارسی**، و ذخیره‌سازی محلی در **SQLite**.

> داده‌ها فقط روی کامپیوتر خودِ کاربر می‌مانند؛ تنها درخواست‌های هوش مصنوعی از اینترنت عبور می‌کنند.

---

## ویژگی‌ها

- **چت هوشمند** با هر سرویس سازگار با OpenAI (OpenAI، OpenRouter، Groq، Ollama، LM Studio، vLLM و …) — فقط `base_url` + `api_key` + `model` را تنظیم کنید.
- **سه شخصیت دستیار:** 🌿 نیلا (همدل)، 💪 آرش (مربی رک)، 🔬 دکتر رها (علمی و محتاط).
- **ثبت خودکار با زبان طبیعی:** «ناهار دو کفگیر چلو خوردم» → در SQLite ثبت می‌شود و کارت تأیید نشان داده می‌شود.
- **پایگاه‌دادهٔ محلی غذاهای ایرانی** (۱۱۵+ قلم با ماکروهای واقعی) و **حرکات ورزشی** (۵۷+ با MET).
- **داشبورد امروز:** حلقه‌های کالری/پروتئین/آب/سوزانده، ثبت سریع وزن/آب/خواب.
- **گزارش‌ها:** نمودار روند وزن، کالری ورودی/خروجی، درشت‌مغذی‌ها، آب و تمرین (Chart.js لوکال).
- **محاسبات علمی:** BMI / BMR / TDEE (Mifflin‑St Jeor)، هدف کالری و درشت‌مغذی با محدودیت‌های ایمنی.
- **جست‌وجوی نادقیق فارسی:** «قرمه سبزی» ← «قورمه سبزی»، «كباب» ← «کباب کوبیده» (تحمل حرف افتاده و املای عربی).

## پیش‌نیاز

- Node.js ≥ 18 (توصیه: 20+)
- برای ساخت نسخهٔ نهایی، دسترسی به GitHub Releases (باینری الکترون) لازم است.

```
cd app
npm install          # الکترون + better-sqlite3 + بازسازی بومی
npm start            # اجرای حالت توسعه
npm test             # اجرای همهٔ آزمون‌ها
npm run dist         # ساخت نصبی/پرتابل ویندوز (NSIS + Portable)
```

> `npm install` سعی می‌کند `better-sqlite3` را برای ABI الکترون بازسازی کند. اگر در محیطی بدون دسترسی به `electronjs.org` بودید، هشدار (نه خطا) می‌بینید؛ `electron-builder` هنگام `npm run dist` خودش آن را انجام می‌دهد. برای حالت توسعه هم می‌توانید `npm run rebuild` بزنید.

## معماری — تصمیم‌های کلیدی و «چرا»

### ۱) چرا `better-sqlite3` فقط در main؟
- **امنیت:** renderer با `contextIsolation:true` و `nodeIntegration:false` اجرا می‌شود و فقط یک آبجکت سفیدشدهٔ IPC (`window.teDiet`) می‌بیند. هیچ `fs`/`require` در مرورگر نیست.
- **سرعت و قابلیت اطمینان:** SQLite تراکنش واقعی و ایندکس می‌دهد؛ بسیار مطمئن‌تر از IndexedDB و بدون سقف حجم.
- **تاریخ‌ها:** همهٔ ستون‌های `day` کلید جلالی `1405-07-15` هستند تا «روز» در رابط و در پایگاه‌داده یکی باشد؛ زمان دقیق در `ts` (ISO UTC).

### ۲) چرا تماس AI از main، نه renderer؟
- کلید API هرگز وارد حافظهٔ renderer نمی‌شود (فقط نسخهٔ ماسکه‌شده).
- مشکل CORS نیست و پروکسی سیستم خودکار اعمال می‌شود.
- پاسخ جریانی (SSE) با رویدادهای `chat:delta/done/error/cancelled` به renderer می‌آید.

### ۳) چرا «قرارداد JSON» به‌جای tool-calling رسمی؟
بسیاری از سرویس‌های سازگار با OpenAI (به‌ویژه خودمیزبان) پیاده‌سازی ناهمگون `tools` دارند. یک بلوک ```action``` در خروجی مدل روی **همه** کار می‌کند. renderer بلوک‌ها را جدا می‌کند، main اجراشان می‌کند، و متن پاک‌شده را نمایش می‌دهد. انواع: `log_meal`, `log_workout`, `log_weight`, `log_water`, `log_sleep`, `set_goal`, `update_profile`.

### ۴) چرا config.json در userData؟
در نسخهٔ نصب‌شده پوشهٔ برنامه داخل asar و فقط‌خواندنی است؛ پس `config.json` همراه فقط «مقدار اولیه» است و در اولین اجرا به `userData` کپی می‌شود. از آن پس همیشه نسخهٔ userData خوانده/نوشته می‌شود.

### ۵) چرا یک ماژول UMD مشترک برای جلالی/تغذیه/ورزش/NLP؟
تا اعدادی که کاربر می‌بیند با اعدادی که مدل می‌بیند یکی باشد و هیچ دوگانگی بین main و renderer پیش نیاید.

## امنیت

- `contextIsolation` + `nodeIntegration:false` + `sandbox:true` + CSP سخت‌گیرانه.
- ناوبری به دامنهٔ خارجی ممنوع؛ لینک‌ها در مرورگر سیستم باز می‌شوند.
- خروجی مدل **همیشه escape** می‌شود و سپس زیرمجموعهٔ امنی از Markdown رندر می‌شود.
- فهرست سفید کانال‌های IPC در preload؛ شنونده‌های دلخواه ثبت نمی‌شوند.
- کلید API ماسکه می‌شود؛ مسیرهای قابل باز شدن محدود به userData هستند.

## محدودیت‌های پزشکی (در پرامپت و UI)

اپ جایگزین پزشک نیست. برای بارداری/شیردهی، دیابت نوع ۱، بیماری کلیوی/قلبی، اختلال خوردن و مصرف دارو، به پزشک ارجاع می‌دهد. کاهش وزن > ۱ کیلو در هفته و رژیم < ۱۲۰۰ کالری توصیه نمی‌شود (در `nutrition.js` کران‌دار شده).

## آزمون‌ها

`npm test` شامل ۹۹+ آزمون است:
- **jalaali / db / actions / domain:** واحدها با SQLite واقعی.
- **ai:** کلاینت در برابر یک سرور ساختگی OpenAI (SSE، خطاها، timeout، لغو).
- **e2e-chat:** مسیر کامل `chat:send` → پرامپت → پاسخ جریانی → action → SQLite.
- **renderer:** `index.html` و همهٔ اسکریپت‌ها داخل jsdom با هستهٔ واقعی (ipc.js + db.js) اجرا می‌شوند.
